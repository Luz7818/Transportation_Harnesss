快速开始

三分钟跑通「启动服务 → 登录看板 → 完整自进化」的最小闭环。

终端
# 1. 安装依赖(仅首次)
pip install -r requirements.txt

# 2. 启动服务,默认 http://127.0.0.1:8765
python webapp/app.py

# 3. (可选)重置种子数据 / 命令行跑一轮完整自进化
python scripts/seed_cases.py
python -m harness.evolve

# 4. 端到端不变量校验,预期输出 VERIFY PASS
python scripts/verify.py

浏览器打开 http://127.0.0.1:8765,默认账号 admin / harness123(登录后请在左下角修改密码); 内网演示可设 AUTH_MODE=open 免登录。公网部署、Docker 与小程序接入见项目根目录 DEPLOY.md。

核心概念

四个概念构成全部模型,其余都是围绕它们的工程化。

1replaycase

可重放的最小评测单元 = 复现问题的输入数据集 + 期望结论 + 判分规则(checks)。按失败标签分目录存放在 cases/,一个 case 一个 JSON,可纳入 git 管理。

2评测集(evalset)

replaycase 的版本化清单,存放在 evalsets/。评测集与 case 分离:同一批 case 可以组成多套评测集(如全量集 / 雨天场景集),评测历史因此可追溯。

3管线版本

被测的交通分析算法,pipeline/versions.py 中 v0(基线)/v1/v2(两轮迭代)共存注册。版本只进不改 —— 出现新 badcase 时新增 v3,而不是修改 v2。

4自进化闭环

评测 → 定位失败 → 迭代 → 回归验证的循环。迭代纪律固化在代码里:最多 2 轮、单轮提升 <5% 即停(收益递减)、任何已通过案例回归则一票否决。

判分规则(checks)类型

每条 case 的 checks 数组声明「什么样子算修好了」,由判分器执行:

type语义关键字段
classify某路段的拥堵等级应等于期望值segment, expected
metric指标在容差内近似相等;segment 缺省表示校验全局字段(如 global_congestion_index)segment?, field, expected, tol
no_crash管线必须正常返回、不抛异常(健壮性)—
recommendations每个拥堵/严重拥堵路段都必须给出处置建议—
congested_empty拥堵路段列表应为空(空数据集优雅降级)—
conclusion_keyword结论文本必须覆盖给定关键词(启发式 judge,可替换为真实 LLM)keywords[]

replaycase 数据结构

cases/阈值错误/rc-0001.json
{
  "case_id": "rc-0001",
  "title": "学府路(V/C 0.91)被按车速误判为「严重拥堵」",
  "label": "阈值错误",            // 失败类别,用于聚类定位
  "dataset_name": "base",          // 复现所需数据集
  "checks": [
    { "type": "classify", "segment": "S-02", "expected": "拥堵" },
    { "type": "metric", "segment": "S-02", "field": "saturation", "expected": 0.91, "tol": 0.01 }
  ],
  "source": "线上点踩",
  "notes": "..."
}

六步工作流

每一步都有页面与 API 承接,这是本产品的标准使用路径。

  1. 收集反馈线上点踩、人工抽检或外业巡查发现坏结果。
  2. 沉淀 replaycase看板「Case 管理」填写表单,或调 POST /api/cases;保存到 cases/<标签>/ 并自动加入当前评测集。
  3. 运行评测看板点「运行评测 / 运行完整自进化循环」,或 python -m harness.evolve。
  4. 定位失败评测看板按失败标签聚类展示通过率,剩余失败一目了然。
  5. 迭代管线在 pipeline/versions.py 新增 v3 并注册,每轮只改一类问题。
  6. 回归验证「版本对比」逐 case 差分 + python scripts/verify.py 不变量校验,通过才算合入。

循环回到第 1 步:新的 badcase 持续回流,评测集随之增长,管线得分被一次次推向更高。

鉴权方式

三类身份,一套中间件:浏览器走会话 Cookie,机器客户端走令牌,内网演示全放行。

模式启用方式行为
login(默认)不设置或 AUTH_MODE=login除 /api/auth/*、/api/health、/help 外,所有 /api/* 需要登录会话(HttpOnly Cookie);配置 AUTH_TOKEN 后也接受 X-API-Token 头。
openAUTH_MODE=open全部放行,以 demo 身份进入工作台。仅限内网演示。
令牌(机器客户端)AUTH_TOKEN=<强随机串>微信小程序 / 脚本以请求头 X-API-Token: <串> 访问,无需登录;令牌比较为时序安全。

安全内建:口令 PBKDF2 哈希存储(12 万次迭代)、登录连续失败 5 次锁定 10 分钟、 HMAC 签名会话(7 天)、文件名白名单防路径穿越。

登录并携带会话
# 登录,保存 Cookie
curl -c cookies.txt -X POST http://127.0.0.1:8765/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"username":"admin","password":"harness123"}'

# 带 Cookie 访问受保护接口
curl -b cookies.txt http://127.0.0.1:8765/api/cases

# 或:机器客户端用令牌头(需服务端设置 AUTH_TOKEN)
curl -H "X-API-Token: <你的令牌>" http://127.0.0.1:8765/api/health

错误码约定

所有错误返回统一 JSON 结构 {"detail": "人类可读的中文说明"}。

状态码含义典型场景
400参数校验失败标题超长、路段不在数据集、期望等级非法、名称含路径字符
401未登录或会话过期login 模式下缺少 Cookie / 令牌,口令错误

Python(requests)

python
import requests

BASE = "http://127.0.0.1:8765"
H = {"X-API-Token": "<你的令牌>"}   # 服务端启动时设置 AUTH_TOKEN

# 1) 用 v2 分析雨天情景
out = requests.post(f"{BASE}/api/analyze", headers=H, timeout=10,
                    json={"version": "v2", "dataset_name": "rain_peak"}).json()
print(out["summary"])

# 2) 沉淀一条 replaycase 并加入评测集
requests.post(f"{BASE}/api/cases", headers=H, timeout=10, json={
    "title": "学府路应判为拥堵而非严重拥堵", "label": "阈值错误",
    "dataset_name": "base", "segment": "S-02",
    "expected_level": "拥堵", "expected_saturation": 0.91,
})

# 3) 跑一轮完整自进化
summary = requests.post(f"{BASE}/api/evolve/run", headers=H, timeout=120,
                        json={"evalset": "evalset_v1"}).json()
print(summary["best"], summary["stop_reason"])

端到端完整示例

用一段脚本走完「沉淀 → 评测 → 自进化 → 对比」闭环,可直接作为接入模板。

bash
BASE=http://127.0.0.1:8765
H="X-API-Token: <你的令牌>"
J="Content-Type: application/json"

# 1) 沉淀一条 badcase(自动加入评测集)
curl -s -X POST $BASE/api/cases -H "$H" -H "$J" -d '{
  "title":"学府路应判为拥堵而非严重拥堵","label":"阈值错误",
  "dataset_name":"base","segment":"S-02","expected_level":"拥堵"}'

# 2) 对 v2 跑单版本评测
curl -s -X POST $BASE/api/eval/run -H "$H" -H "$J" \
     -d '{"version":"v2","evalset":"evalset_v1"}'

# 3) 一键自进化(基线 → 最多 2 轮 → 归档)
curl -s -X POST $BASE/api/evolve/run -H "$H" -H "$J" -d '{"evalset":"evalset_v1"}'

# 4) 取最近两份报告做回归差分(报告 ID 从 /api/reports 获取)
curl -s "$BASE/api/compare?a=report_v1_20260915T021603&b=report_v2_20260915T021603" -H "$H"

常见问题

LLM 用在哪里?没配 API Key 会怎样?
LLM 只做规则判不了的三件事:坏例沉淀助手(草稿需人工确认)、结论文本质量评分(LLM-as-Judge)、失败诊断(分析者+评审者双智能体)。未配置 LLM_API_KEY 时自动降级为离线确定性 Mock —— 全功能可演示、零成本、可复现。配置三个环境变量即可接入任意 OpenAI 兼容端点,详见 docs/LLM.md 与「智能助手」页。
默认账号是什么?如何重置?
首次启动自动创建 admin / harness123(可用环境变量 ADMIN_USER / ADMIN_PASSWORD 覆盖)。忘记密码:停止服务,删除 webapp/auth.json 后重启即重新生成。
如何新增管线版本 v3?
在 pipeline/versions.py 实现 analyze_v3(segments) 并登记到 PIPELINES 与 CHANGELOG,看板/评测自动识别;自进化从基线起逐轮验证登记版本 —— 增量验证可传 baseline: "v2"(API)或 --baseline v2(CLI),单轮上限可用 EVOLVE_MAX_ROUNDS 调整。版本只进不改,历史可回放。
如何接入自己的数据?
把路段快照写成 pipeline/data/<名称>.json(字段结构参照 base.json),即出现在「分析提交」与 Case 表单下拉中;评测集在 evalsets/ 中建同名清单 JSON。
端口被占用 / 修改监听地址?
PORT=8766 HOST=0.0.0.0 python webapp/app.py;公网部署务必同时设置 AUTH_TOKEN。
评测数据存在哪里?会不会丢?
全部落盘本地:cases/ evalsets/ reports/ 三个目录,拷贝即迁移;Docker 部署时以数据卷挂载,容器升级不丢资产。
判分能接入真实大模型吗?
可以。继承 harness/judge.py 的 BaseJudge 实现打分逻辑,替换 CompositeJudge 成员即可,runner 与报告零改动;当前 HeuristicJudge 是离线确定性替身。
